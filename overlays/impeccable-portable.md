## SUPERBROWKY portable contract

This is SUPERBROWKY's reviewed **guidance-only adaptation of Impeccable 4.9.2**.
It retains selected upstream craft references and uses the manual workflow in
[PORTABLE.md](PORTABLE.md). It is not the upstream engine distribution.

- Read the user's latest request, corrections, existing implementation and
  mapped project context directly. Missing `PRODUCT.md` does not block a
  scoped refinement when the existing project provides enough evidence.
- The user's brief, approved brand/system, platform and accessibility needs
  outrank stylistic defaults in every reference. A new screen does not
  authorize a new visual identity. Use the named template and actual assets.
- Continue work already authorized. Ask only when an unresolved choice changes
  meaning, scope, established identity, required assets or action authority.
- Reviews and audits remain read-only unless fixes were requested. Never
  create context files, sidecars, reports or hook settings as hidden setup.
- Use only actually available tools, skills and agents. Prefer MCP/API for
  structured data; browser automation needs explicit visual-QA authorization.
  A craft reference does not grant permission to install, publish or spend.
- For substantive design follow craft owner → builder → owner verification →
  independent review. The independent reviewer must not have authored the
  artifact or set its direction. Human acceptance stays with the human.
- Inspect the exact final artifact, relevant states and complete user path.
  Report unverified behavior as `PARTIAL`; a source review is not visual QA.

### Modes

Choose the mode for the requested surface, not for the entire product:

- **Operate:** complete a task; familiar controls, clear state, precision.
- **Read:** understand information; structure, prose measure, navigation.
- **Persuade:** decide and act; hierarchy, truthful claims, strong imagery.
- **Experience:** engage with the work; let the artifact lead.

Read [operate.md](reference/operate.md) for product UI, with the relevant
[Operate](reference/mode-operate.md), [Read](reference/mode-read.md), or
[Persuade / Experience](reference/mode-persuade.md) mode reference.

Read only the references needed for this task. Before an authorized UI edit,
read [craft-floor.md](reference/craft-floor.md) and the existing design system.

No argument is a request for a brief explanation, not permission to run a tool.
The upstream binary, launchers, live/generate mode, hooks, pin/unpin, automatic
detectors, engine doctor, foundations wizard and bundled agent definitions are
**not included**. Do not download them, invoke an engine elsewhere on PATH, or
simulate their receipts. Use the available manual craft route where it answers
the request; disclose the limitation when the user asks for an omitted mode.
